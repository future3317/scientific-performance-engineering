# ACRE Method-Core Consolidation Plan

> **For agentic workers:** Execute this plan inline with the existing tests; keep one canonical implementation and one public façade.

**Goal:** Consolidate ACRE into one Active Counterexample-guided Causal Rule Evolution method core with asymmetric evidence, adaptive experiment selection, typed relation identification, unified governance, and a conservative routing boundary.

**Architecture:** `core/models.py` owns typed contracts. `core/acre/` owns the method: evidence policy, CEGIS, factorial inference, adaptive acquisition, routing, and the `AcreEngine` façade. `core/governance.py` owns the shared rule/relation lifecycle. Benchmark code constructs environments, executes interventions, and evaluates sealed outcomes; it does not implement method logic.

**Tech Stack:** Python 3.11, stdlib dataclasses/JSON, the existing project environment, and the existing pytest plus contract-script test entry points.

## Global Constraints

- Preserve the formal SPE-EvoBench task semantics and do not add ACRE pilot results to formal headline metrics.
- New evidence writers emit canonical EvidenceEvent v2; legacy evidence is read-only normalization input.
- Representative evidence may update effect/confidence/promotion statistics; adversarial evidence may only falsify, specialize, or quarantine.
- Hidden truth is available only to offline evaluators, never to acquisition stopping or routing decisions.
- Relation semantics have one source of truth: `RelationSpec` and `RelationState`.
- Do not retain parallel `RuleCandidate`, `InteractionEvidence`, or benchmark-owned method implementations.
